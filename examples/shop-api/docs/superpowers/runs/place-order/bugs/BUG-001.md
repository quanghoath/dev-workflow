# BUG-001 · Double-clicking the "Place order" button creates 2 orders

- **Found in:** P4 · scenario `UI-2` · related AC: `AC-1`
- **Severity:** fail
- **Status:** fixed · loop 1/3

## Reproduction

1. Open `/cart` with 2 products.
2. Use `evaluate_script` to click the "Place order" button twice in a row (~50 ms apart).

**Expected:** 1 `POST /api/orders` request, 1 order.
**Actual:** 2 requests, 2 `PENDING` orders, stock deducted twice.
**Evidence:** `evidence/ui-2-network.md` (network list from `list_network_requests`).

## Root cause

The button is locked with an `isSubmitting` state, but the state only updates on the next render. The second click arrives before that render, so the handler still runs. The API has no duplicate protection either, so it accepts both.

## Fix

- Reproducing test: `CartPage.test.tsx::does not send 2 requests on repeated clicks` (red before the fix, green after).
- Changes:
  - `src/cart/CartPage.tsx`: lock with `useRef` directly in the handler, before the `await`.
  - `OrdersController`: accepts an `Idempotency-Key` header; the same key within 10 minutes returns the order already created.
- Re-run: `UI-2` → pass; all of P4 (regression) → pass.
